# 관리자 가이드

서비스 관리 콘솔(`/admin`)에서 다루는 설정 가운데 동작을 알고 써야 하는 것을
적는다. 화면 구성은 [사용자 가이드 §2.9](guide.md#29-서비스-관리-콘솔-admin),
배포와 환경 변수는 [오프라인 배포](OFFLINE.md)를 본다.

## 다른 서비스로 보내기

사람과 함께한 순간의 기록(기억)은 muni 의 문서가 되고 ptium 의 슬라이드가 되어
weekly 의 보고로 들어간다. 형식은 이미 맞았다 — Orbit 은 마크다운을 만들고
그쪽은 마크다운을 읽는다 — 단계마다 사람이 파일을 내려받아 다시 올리는 손만
남아 있었다. **다른 서비스로 보내기** 탭은 그 손을 없앤다.

Orbit 은 사내 표준(`HANDOFF-STANDARD.md`)의 **보내는 쪽**이며 형식은 `markdown`
하나다. 받는 쪽은 만들지 않는다 — Orbit 으로 문서를 들여올 길은 없다.

**기본값은 비어 있다.** 허용 목록이 비어 있으면 기억 화면에 보내기 단추가
나타나지 않는다. 새로 설치한 곳에서는 아무것도 달라지지 않는다.

### 어떻게 넘어가는가

1. 사용자가 **기억** 화면에서 카드의 보내기(종이비행기) 단추를 눌러 서비스
   이름을 고른다. 단추는 **검토가 끝난(승인된) 기억**에만 있다. 검토 대기·반려
   상태의 기억은 승인 절차를 건너뛰어 밖으로 나가지 않는다.
2. Orbit 이 그 기억을 마크다운(제목, 함께한 사람, 언제, 주제, 본문)으로 만들고
   `POST /api/v1/handoff/claims` 로 **표(claim)** 를 발급한다 — 256비트 난수,
   **5분**, **한 번**만 쓸 수 있고, 그 사용자의 그 기억 하나에만 묶인다.
3. 브라우저가 새 창에서 받는 서비스의
   `https://<서비스>/handoff?source=<Orbit 주소>&claim=<표>` 를 연다.
4. 받는 서비스가 `GET <Orbit 주소>/api/v1/handoff/claims/<표>` 로 문서를 받아
   간다. 로그인은 없다 — 표가 곧 자격이다. 받아 가는 순간 표는 지워지고, 두
   번째 요청·만료된 표·발급된 적 없는 표는 모두 같은 `404` 로 답하며 이유를
   구별해 주지 않는다.

문서는 표를 발급하는 순간 만들어 표와 함께 저장되므로(`handoff_claims`, 표는
SHA-256 다이제스트로만 저장), 받는 쪽이 가져가는 바이트는 표가 알린 `bytes`
그대로다. 만료된 행은 다음 표를 발급할 때 정리된다.

`source` 는 **일반 → 서비스 공개 URL** 의 오리진이다. 받는 쪽은 이 값을 자기
허용 목록과 대조하므로, 공개 URL 이 받는 쪽 목록의 표기와 정확히 같아야
한다(스킴·호스트·포트). 공개 URL 이 오리진 모양이 아니면 요청이 들어온 주소를
쓴다.

### 허용 목록 설정

관리자 → **다른 서비스로 보내기**. **서비스 추가**로 줄을 만들고 **목록 저장**
을 누른다. 설정은 `settings` 테이블의 `system:handoff` 행에 있고 저장 즉시
적용된다.

| 항목 | 뜻 |
| --- | --- |
| 이름 | 단추 메뉴에 보이는 이름. 예: `Ptium` |
| 주소 (오리진) | `https://ptium.intra` 처럼 **스킴과 호스트(포트)까지만**. 경로·쿼리·자격 증명이 있으면 저장되지 않는다. 같은 주소를 두 번 적을 수 없다. 대소문자와 끝의 `/` 는 저장할 때 다듬는다. |
| 받는 형식 | 그 서비스가 받는 형식(표준의 형식 표: `markdown` `docx` `csv` `xlsx` `txt` `pptx`). Orbit 은 `markdown` 만 보내므로 **`markdown` 이 없는 항목은 저장되어도 메뉴에 오르지 않는다.** |

표준의 형식 표대로면 `muni`·`ptium`·`weekly` 가 `markdown` 을 받는다. `kanpic`
은 받지 않으므로 적어도 메뉴에 나오지 않는다. 목록은 20개까지다.

API 로는 `PUT /api/v1/admin/settings/handoff` 에 아래 모양을 보낸다.

```json
{"targets": [
  {"name": "Ptium",  "origin": "https://ptium.intra",  "formats": ["markdown", "docx", "csv", "xlsx", "txt"]},
  {"name": "Weekly", "origin": "https://weekly.intra", "formats": ["markdown", "docx", "pptx"]}
]}
```

### 받는 쪽에 알려 줄 것

받는 서비스의 관리자는 자기 허용 목록에 Orbit 의 오리진(위 `source`)을 적어야
한다. 그쪽 목록에 없으면 받는 서비스는 Orbit 에 아무 요청도 보내지 않고
거절한다 — 그것이 표준이다.

### 로그와 감사

- 표는 로그에 남지 않는다. 요청 실패 로그는 이 경로를
  `/api/v1/handoff/claims/{claim}` 으로 가려 적는다.
- 감사 로그에는 `memory.handoff` (기억 id, 형식, 바이트 수)만 남는다. 표는 없다.
- API 키로 표를 발급하려면 `memories:read` 권한이 있어야 한다.

### 확인 절차

1. 목록이 비어 있을 때 기억 화면에 보내기 단추가 없는지 본다.
2. 서비스를 하나 적고 저장한 뒤 승인된 기억 카드에 단추가 나오는지, 고르면 새
   창에 받는 서비스의 `/handoff?source=…&claim=…` 가 열리는지 본다. 팝업이
   막히면 화면이 그렇게 말하고 여는 링크를 준다.
3. 같은 표로 두 번 받으면 두 번째는 `404` 다.
4. 받는 서비스에서 문서가 열리고 출처가 Orbit 으로 남는지 본다.
